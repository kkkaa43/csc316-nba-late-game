# Desperation Meter: how NBA teams play when they trail late

**Live site:** https://kkkaa43.github.io/csc316-nba-late-game/
**Team:** Jinhao Zhang, Herui Zhang, Shiyuan Lyu (CSC316 Data Visualization, University of Toronto, Fall 2026)

An interactive data story for sports bettors who know basic NBA statistics. Using every fourth quarter of
the 2024–25 NBA regular season (1,230 games, ESPN play-by-play), it shows that teams trailing late shoot
faster and take more threes as time runs out, but their chance of winning keeps falling.

> Main message: when NBA teams trail late, they shoot faster and take more threes as time runs out,
> but that urgency does not turn into comebacks.

## Visualizations

| # | Sketch ID | Chart | Question it answers | Component |
|---|---|---|---|---|
| 1 | (story support) | Comeback-rate heatmap | How often do trailing teams come back, by deficit and time left? | `ComebackHeatmap.svelte` |
| 2 | J1 | Multi-series line chart | Does the three-point share change with deficit and time? | `ThreePointChart.svelte` |
| 3 | J4-R (novel) | Tactical Fingerprint Map: 3-spoke glyph + comeback arc per game state | How do several habits change together? | `FingerprintMap.svelte` |
| 4 | S4 | Diverging accuracy heatmap (FG% / 3P%) | Do rushed late shots still go in? | `AccuracyHeatmap.svelte` |
| 5 | J2 | Bubble chart, small multiples by deficit | Do teams that speed up come back more often? | `PaceChart.svelte` |
| 6 | H4 | Horizontal bar chart with 95% intervals | Which teams lean on the three in the same game state? | `TeamBars.svelte` |

**Linked views.** Charts 1–4 share one selection (deficit band × time window, `src/lib/state.svelte.js`).
Clicking a cell, point or glyph in any of them highlights the same game state in the others, highlights
that deficit's panel in chart 5, re-filters chart 6 to that exact state, and opens a sticky summary bar.
Clicking a bubble in chart 5 selects its deficit at the 5:00 mark. Every interactive mark is also
reachable with Tab and activated with Enter or Space.

## Run the website

Requires Node.js 20+.

```bash
npm install
npm run dev          # http://localhost:5173
npm run check        # svelte-check, should report 0 errors and 0 warnings
npm run build        # static site in build/
```

The site is static (adapter-static). It reads the CSV files in `static/data/` with `d3.csv`.
Pushing to `main` deploys it to GitHub Pages through `.github/workflows/deploy.yml`, which sets
`BASE_PATH=/csc316-nba-late-game`.

## Rebuild the data

Requires Python 3.10+.

```bash
python -m venv .venv && .venv/bin/pip install -r scripts/requirements.txt
.venv/bin/python scripts/build_data.py --season 2025      # downloads ~21 MB once, caches it in data/raw/
.venv/bin/python -m unittest discover -s tests -v         # 9 unit tests
```

Use `--input path/to/play_by_play_2025.parquet` to work from a file you already have. The script writes
the six files in `static/data/` and the cleaned event table `data/cleaned/q4_events.csv` (11 MB, not
committed; it is regenerated by the command above and included in the final ZIP).

Every column of every file is documented in **[data/DATA_DICTIONARY.md](data/DATA_DICTIONARY.md)**.

### Source

ESPN NBA play-by-play published by the SportsDataverse / hoopR project:
`https://github.com/sportsdataverse/sportsdataverse-data/releases/download/espn_nba_pbp/play_by_play_2025.parquet`
([loader docs](https://py.sportsdataverse.org/docs/nba/reference/loaders/other)).
The SHA-256 of the file used is recorded in `static/data/metadata.json`. This project is not affiliated
with the NBA or ESPN.

### Cleaning steps (`scripts/build_data.py`)

1. Keep regular-season rows (`season_type == 2`), drop rows without game, play number or team ids, and
   de-duplicate `(game_id, game_play_number)`.
2. Drop games that are not part of the 1,230-game schedule: the NBA Cup final (does not count in the
   standings) and the three shortened All-Star games (removed by requiring a winner and ≥ 60 points per side).
3. Sort by `game_play_number` (chronological; ESPN's `sequence_number` is not) and parse the clock.
4. Reconstruct the score **before** each event from the previous row, because ESPN stores the score after it.
   A made three is therefore classified by the deficit the shooter faced.
5. Flag field-goal attempts (`points_attempted` 2 or 3), threes, makes, turnovers (ESPN type ids 62–90
   and 206, which includes "Traveling" and excludes "No Turnover") and personal fouls.
6. Keep fourth-quarter events (overtime excluded) and bin them by deficit (1–3, 4–6, 7–10, 11+) and time
   left (9–12, 6–9, 3–6, 0–3 minutes; the 0–3 bin includes 3:00).
7. Aggregate per bin; see the data dictionary for each measure's exact definition.

## Limitations

One season; a few cells hold only a few hundred team-games; no shot location, line-up or possession data;
"per minute" rates use game-clock time spent trailing (both teams' possessions). All rates are
descriptive historical frequencies, not predictions or causal effects.
